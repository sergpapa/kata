# Earlier feedback conversations

Milestone 3. Start over hides a feedback conversation and keeps it in the store (PF7). Until this
slice nothing could show it again. Now the lesson page lists an activity's earlier conversations,
read-only, and Export can carry them. Nothing is deleted or edited, and Claude is never asked
anything new. Amends `docs/specs/export.md` EX2, EX11, EX13 and EX15; keeps ADR 0021's rules.

## Decisions taken with the owner (2026-11-19)

1. **Save everything; choose at export.** Saving stays automatic. Which attempts go to the author is
   a choice made when exporting.
2. **Only conversations with a reply count as earlier conversations.** A hidden conversation with
   no completed Claude reply (what every Try again leaves behind) is not listed and not exported. It
   stays in the store.
3. **Export offers one three-way choice** in place of the checkbox: None, Current only, Current and
   earlier. Default None.

## Acceptance criteria

### What the server sends

- **EC1.** Each activity's feedback area, in the lesson answer (`feedback.activities[]`) and from
  `GET …/activities/:activityId/feedback`, carries `earlier`: that activity's conversations hidden
  by Start over that have at least one Claude turn with outcome `complete`. Each item has
  `conversationId`, `startedAt`, `clearedAt` and `turns`, the turns in the same shape and order as
  the current conversation's. The list is newest first: latest `clearedAt` first, then higher
  `conversationId` first. With none, `earlier` is `[]`.
- **EC2.** A hidden conversation with no complete Claude turn is never in `earlier` (its row and
  turns stay in the store). The current conversation is never in `earlier`. Another activity's
  conversations are never in it.
- **EC3.** `POST …/feedback/clear` answers `{ "state": "cleared", "earlier": [...] }`, the list as it
  is after the hide. The 409 `feedback_conversation_changed` body carries `earlier` beside
  `conversation`.

### The lesson page

- **EC4.** When `earlier` has at least one conversation, the feedback area ends with a closed
  disclosure whose summary reads "Earlier conversations (<n>)". Opened, it lists them in the order
  sent. Each is introduced by "Started over <time> on <day>" (the reader's own time zone, the words
  PF20 uses for a pause), and shows its turns as the current conversation does: the You and
  "AI feedback · <model>" labels, the "What you sent" disclosure, a failed turn's reason and any
  unfinished text, Claude's words through the lesson Markdown renderer.
- **EC5.** Nothing inside the disclosure can change or continue a conversation: no message box,
  Send, Start over, Try again or model picker.
- **EC6.** With `earlier` empty or absent (an answer from before this slice) there is no disclosure
  and the area draws as before.
- **EC7.** Start over on a conversation with a reply puts it first in the disclosure and raises the
  count by one, without reloading the page. Try again on an unanswered first question leaves the
  count as it was. A 409 `feedback_conversation_changed`, and every poll for a reply (PF15), replace
  the list with the one the server sent when the body has one.
- **EC8.** The disclosure shows in every availability state (ready, paused, unavailable) and while
  a reply is being written.
- **EC9.** The summary is reached by Tab and toggled by Enter or Space. Each earlier conversation's
  turn list is named "Earlier conversation, started over <time> on <day>"; the current one keeps
  the name "Conversation". The area fits 375, 768 and 1440 with no horizontal page scroll.

### Export

- **EC10.** `conversations` takes `0`, `1` or `all`. `0` and `1` behave as before (EX9–EX11).
  Anything else, including empty or given twice, answers 400 as EX13 does, naming
  `` `conversations` ``.
- **EC11.** With `conversations=all`, each activity shows its current conversation as EX10 does,
  then each of its earlier conversations (as EC1 and EC2 choose them, newest first) as its own
  section headed `#### AI feedback, earlier conversation started <startedAt>, started over
<clearedAt> (generated by Claude, not a review by the author)`, its turns written as EX10 writes
  them. An activity with only earlier conversations shows those. Conversations of a dropped
  activity are still not carried (EX8).
- **EC12.** The context line is `AI feedback conversations: not included` for `0`,
  `AI feedback conversations: included` for `1`, and
  `AI feedback conversations: included, with earlier conversations` for `all`. With `0` or `1` no
  earlier conversation's text, failure or model appears.
- **EC13.** The Export card's checkbox becomes a group named "AI feedback conversations" with three
  radio buttons, "None" (chosen at load), "Current only" and "Current and earlier", sending `0`, `1`
  and `all`. Changing the choice clears a stale "Downloaded", as the checkbox did. The group is
  operable by keyboard (Tab into it, arrow keys between choices) and fits 375, 768 and 1440.

## Assumptions (defaults, not asked)

- The list rides on the lesson answer, not a separate request: it is small, and one load keeps
  PF8's "survives a refresh" for free.
- Earlier conversations are newest first on the page and in the file, as earlier answer revisions
  are (EX6).
- Times in the file are stored UTC ISO 8601, as everywhere in the export. The page uses local time.
- A conversation that had a reply and then a failed follow-up is shown whole, failure included.
- The disclosure starts closed on every load; whether it was open is not remembered.
- The Export group is a `fieldset` with its `legend`, so its role is `group`.
- jsdom has no layout, so the widths in EC9 and EC13 are checked by `npm run screenshots` with a
  lesson page that has an earlier conversation open, and by the design review; the keyboard parts
  rest on native `details`/`summary` and one shared radio `name`, which the tests pin.

## Out of scope

Restoring or continuing an earlier conversation. Deleting anything. Choosing individual
conversations for export. Showing the conversations Try again replaced. Any change to how a
conversation is asked, streamed or stored.

## Tests re-aimed by this spec

EC13 replaces the checkbox, so two `exportCard.test.tsx` tests change their aim with it, as EX15
re-aimed a dashboard test: "replaces the old records text with range pickers, an unticked box and
Export" now expects the radio group with None chosen, and "asks for the range chosen, with
conversations when the box is ticked" now chooses Current only. Both keep their URL assertions.

## Done means

On a lesson page the owner presses Start over on a conversation, and "Earlier conversations (1)"
appears under the feedback area; opened, it shows that conversation read-only. After a Try again
the count does not move. On the course page they choose "Current and earlier" and export: the file
has each current conversation, then the earlier ones newest first, each under its own labelled
heading. With "Current only" the file is as it was before this slice.
